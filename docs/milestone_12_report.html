1. Introduction and Objective

This project builds a small search engine for text. The user types a query, and the system returns the documents that match it best, ranked from most to least relevant.

Each document is converted into a list of numbers (a vector). The query is converted in the same way. The system then measures the angle between the query vector and each document vector using cosine similarity. A smaller angle means the document is more relevant.

The whole system is written from scratch using only Python's standard library. External retrieval or machine-learning frameworks (for example Scikit-learn, NLTK or NumPy) are not allowed. This keeps the focus on data structures, algorithm complexity and program correctness (invariants), and applies discrete mathematics and linear algebra directly to software.

This report covers Milestone 1: the requirements, the mathematical specification, the architecture, the choice of representation model, the data schema, and the program invariants. No implementation code is part of this milestone.

4. Mathematical Specification

4.1 Definitions

  • Corpus: C = {d1, d2, …, dN}, a set of N documents.
  • Tokenizer: a function T that maps a string to a list of tokens (lowercase words with no punctuation).
  • Vocabulary: V = {t0, t1, …, tD−1}, the set of all unique tokens that appear in C. It is sorted alphabetically so that the order is deterministic. D = |V| is the dimension of the vector space.
  • Index map: idx: V → {0, 1, …, D−1}, where idx(ti) = i.
  • Normalized TF vector of a document d: a vector d ∈ ℝD where
    di = count(ti, d) / |T(d)|
    that is, the number of times ti appears in d, divided by the total number of tokens in d.
  • Query vector q is built the same way from the query string, using the same V. Query words that are not in V are ignored.

4.2 Vector operations

Dot product:   q · d = Σi=0D−1 qi di
Euclidean norm:   ||d|| = √( Σi=0D−1 di2 )
Cosine similarity:   Score(Q, D) = (q · d) / ( ||q|| × ||d|| )

Cosine similarity is the cosine of the angle θ between the two vectors. It compares the direction of the vectors, not their length, so a long document and a short document about the same topic can still score high.

4.3 Properties

  • Every TF value is ≥ 0, so no angle can exceed 90°. Therefore 0 ≤ Score ≤ 1.
  • Score = 1 means the two vectors point in exactly the same direction (same word proportions). Score = 0 means the two share no words.
  • Multiplying a vector by a positive number does not change the cosine, so the normalization in the TF definition does not change the ranking. It keeps the numbers small and comparable.

4.4 Edge cases

SituationResult
||q|| = 0 (empty query, or no query word is in V)The denominator would be 0. The system returns Score = 0 instead of raising a division error.
||d|| = 0 (empty document)Score = 0 for that document.
Disjoint vocabularies (no shared words)q · d = 0, so Score = 0.
Input is not a stringA TypeError with a clear message is raised.
Floating-point result slightly above 1 (for example 1.0000000002)The score is clamped to the range [0, 1].

5. Selection of the Representation Model (Backbone)

The SDMS template for this milestone asks for a "CNN backbone" selection. That wording was written for an image-retrieval project. In this project the data is text, so the equivalent decision is: which model should turn a document into a vector? The options are compared below.

OptionHow it worksFits this project?
CNN image embeddingsA neural network turns an image into a vector.No. Our data is text, not images.
Neural text embeddings (for example BERT)A trained neural network turns a sentence into a vector.No. It needs ML frameworks and pretrained weights, which breaks the standard-library rule. It is also a black box, so it is hard to explain mathematically.
TF-IDFTF weighted by how rare a word is across the corpus.Possible later. Planned as an optional extension after the basic model works.
Normalized term-frequency VSM + cosine similarity (chosen)Each document is a vector of word frequencies. Closeness is measured by angle.Yes. It is fully transparent, can be built with the standard library, uses linear algebra directly, and every step can be explained and tested.

Decision: the Vector Space Model with normalized term-frequency vectors and cosine similarity.

6. System Architecture

6.1 Data-flow diagram (Level 1)

Reading the diagram: documents are cleaned, a vocabulary is built from them, and each document is projected into a vector. When a user types a query, it goes through the same cleaning and projection, is scored against every document, and the results are sorted.

6.2 Level 0 (context)

User → (query string) → [Retrieval Engine] ← (document collection) ← Corpus files. The engine returns a ranked list of documents with scores to the user.

6.3 Modules and interfaces

FunctionInput → OutputPrecondition / Postcondition
normalize_text(text)str → list[str]Pre: text is a str. Post: tokens are lowercase, contain no punctuation and are not empty.
build_vocabulary(docs)list[list[str]] → dict[str, int]Post: indices are unique and run from 0 to D−1 in sorted-word order.
vectorize(tokens, vocab)list[str], dict → list[float]Post: length equals D; all values ≥ 0; values sum to 1 when the token list is non-empty.
dot_product(a, b)two vectors → floatPre: len(a) == len(b).
euclidean_norm(a)vector → floatPost: result ≥ 0.
cosine_similarity(a, b)two vectors → floatPost: result in [0, 1]; returns 0 if either norm is 0.
search(query, corpus, k)str → list of (doc_id, score)Post: sorted by score (highest first), ties broken by doc_id, at most k results.

6.4 Standard-library boundary

Allowedre, string, math, json, sys, time, collections, heapq, unittest, tracemalloc
Not allowedNumPy, Pandas, Scikit-learn, NLTK, SciPy and any other third-party package

7. Program Invariants and Input Constraints

IDInvariant (must always be true)
I1Every vector has length exactly D = |V|.
I2Every token is a non-empty lowercase string with no punctuation.
I3Vocabulary indices are unique and contiguous (0 to D−1), assigned in sorted order, so the mapping is deterministic.
I4Every TF value is ≥ 0. For a non-empty document the TF values sum to 1.
I5Every cosine score lies in [0, 1].
I6Documents and queries must be str. Any other type raises TypeError.
I7Ranking is deterministic: equal scores are ordered by document id.
I8The vocabulary is built only from the corpus; the query never changes V.

These invariants will be written as assert statements and unit tests in Milestones 2 and 4.

8.4 Inverted index (Milestone 4)

KeyValue
termlist of (doc_id, tf) pairs for documents that contain the term

With an inverted index, a query only needs to look at documents that share at least one word with it, instead of scanning the whole corpus. Per-document norms are computed once and stored.

{
  "documents": [{"doc_id": 0, "title": "doc0", "raw_text": "the cat sat on the mat", "token_count": 6}],
  "vocabulary": {"cat": 0, "dog": 1, "log": 2, "mat": 3, "on": 4, "sat": 5, "the": 6},
  "inverted_index": {"cat": [[0, 0.1667]], "mat": [[0, 0.1667]]}
}
