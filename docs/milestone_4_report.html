1. Objective & Scope Alignment

Milestone 4 transitions the engine from the dense O(N × D) prototype to a memory- and latency-optimized Sparse Vector + Inverted Index architecture (Section 8.3–8.4 of Milestone 1), verifies every program invariant (I1–I8) and edge case via an automated unittest suite (test_vsm.py), and empirically profiles memory and runtime scaling using Python's tracemalloc and time modules (benchmark.py).

Note on SDMS Template Mapping: For our local standard-library text IR engine, "optimization & stress testing" corresponds to replacing dense O(N × D) scoring with sparse posting-list traversal and verifying numerical equivalence across up to 2,000 synthetic documents; "error handling & security/safety" corresponds to strict input-type validation (I6), NaN/infinity rejection, zero-norm protection, floating-point clamping (I5), and zero third-party dependency attack surface (NFR2).

2. Sparse Vector & Inverted Index Optimization

In natural-language corpora, each document contains only a tiny fraction of vocabulary V, leaving >95% of entries in dense vectors equal to 0.0. Milestone 4 introduces four optimized structures in vsm_engine.py (serialized cleanly to JSON in sample_index.json):

StructureRepresentationOptimization Impact
sparse_vectors{doc_id: {term_idx: tf}}Stores only strictly positive TF weights: memory drops from O(N × D) to O(nnz).
doc_norms{doc_id: float}Precomputes ||d|| once at index time so query scoring divides in O(1) without rescanning d.
inverted_index{term: [[doc_id, tf], ...]}Query traverses only posting lists of in-vocabulary query terms, avoiding full corpus scan.
Top-k Selectionheapq.nsmallest(k, ...)Extracts top-k in O(M log k) with deterministic (-score, doc_id) tie-breaking (I7).

5. Complexity & Optimization Analysis

  • Empirical Proof of Dense O(N × D): Scaling N by 20× (100 → 2,000) scaled dense peak memory by 19.9× (680.6 → 13,561.1 KB) and dense query time by 20.2× (122.4 → 2,469.1 ms).
  • Inverted-Index Latency Collapse: Because queries traverse only posting lists for matching query terms rather than all N × D slots, latency stayed at 0.238 ms at N = 2,000—a 10,376× speedup.
  • Peak Memory Reduction: At N = 2,000, the entire sparse schema (raw document store + vocabulary + sparse vectors + precomputed norms + inverted index) consumed 37.7% less peak RAM than the dense float matrix alone.
